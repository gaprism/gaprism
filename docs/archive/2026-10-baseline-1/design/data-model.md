# Persistence model and state contracts

Owner: this document defines records and invariants; [access control](access-control.md) defines visibility and [evidence](evidence-reporting.md) defines artifact lifecycle. This is a logical schema, not an executed migration.

## 1. Conventions

Use PostgreSQL UUID primary keys generated by the application, `timestamptz` for instants, `inet` for IPs and `jsonb` only for bounded versioned payloads/snapshots. Store canonical ASCII DNS names separately from original display input. Use text plus named CHECK constraints for small state vocabularies unless the project later deliberately chooses native enums. Use positive numeric checks for bytes, attempts and budgets; nullable source timestamps mean unknown, never the epoch.

Every assessment-scoped record carries `workspace_id` and `assessment_id`. Run-scoped records also carry `run_id`. Parent tables expose matching unique keys, and composite foreign keys enforce scope equality. Do not rely on RLS to prevent a cross-case relationship. Global identities/configuration do not acquire meaningless assessment columns.

`created_at` is creation time; `observed_at` is source observation time; `collected_at` is retrieval time. Imported Shodan data can be old even when collected now. Derived facts retain supporting observation IDs and rule version. Mutable aggregate/state records have integer `revision`; observations are insert-only under runtime roles.

## 2. Identity and case records

| Record | Required fields beyond ID/timestamps | Constraints/use |
|---|---|---|
| `workspace` | name, enabled | One provisioned workspace initially; no customer provisioning UI |
| `user` | canonical login, active, security/session identifier, locale; Flask-Security credential/MFA fields | Unique login; use extension-supported field conventions after version selection; never return credential columns |
| `membership` | workspace_id, user_id, role (`member/admin`), active | Unique workspace/user; admin is operational authority, not case access |
| `assessment` | workspace_id, supplier_label, scope_ascii, scope_display, created_by, owner_user_id, state, revision | `active/archived`; archive hides from default lists, does not silently extend retention or revoke access |
| `assessment_grant` | workspace_id, assessment_id, user_id, role, can_download, expires_at nullable, revoked_at nullable, granted_by | Unique case/user effective grant; owner invariant below |
| `scan_run` | scoped parent, requested_by, request_key, input_digest, scope_snapshot, profile_version, redacted_config, state, revision, started_at, terminal_at, discovery_status, cutoff_reason, expires_at | Unique case/requestor/request_key; scope/config immutable after start |

Create assessment and owner grant atomically. On creation/transfer, the owner must be an active workspace member with owner role on that case. Transfer changes `owner_user_id` and the relevant grants under one lock. Account deactivation must take effect immediately, including for a compromised sole owner; it must not be blocked by an ownership invariant. Flag affected cases for audited operator reassignment and prevent further owner-only work until resolved. No cascade user deletion: deactivate identities while retaining attribution under retention policy.

## 3. Discovery and observations

| Record | Required fields | Constraints/use |
|---|---|---|
| `host` | scoped parent, name_ascii, name_display | Unique case/name; no cross-case shared host row |
| `run_host` | run_id, host_id, discovery_source, eligibility, exclusion_reason, first_collected_at | Unique run/host; eligibility is a projection from endpoint checks, not a substitute for them |
| `ct_name_observation` | run_id, name/pattern, wildcard flag, CT counts/times if supplied, source_artifact_id nullable | Wildcards remain observations, not executable `host` targets |
| `dns_observation` | run_host_id, query_name, record_type, response_code, answers, TTLs, resolver/vantage, collected_at | Bounded JSON answers; A/AAAA/CNAME plus optional NS/MX metadata; no recursive assessments of external MX/NS targets |
| `endpoint_observation` | run_host_id, ip, port, transport, hostname/SNI, connected_ip, safety_decision, collected_at | One endpoint per run-host/IP/port/transport and check generation; connection results retain peer actually used |
| `certificate_observation` | endpoint_id, fingerprint, SANs, not_before/not_after, chain_trust, hostname_match, time_valid, revocation_state | Unique endpoint/fingerprint/check generation; keep individual failure reasons |
| `check_result` | run_id, logical_check_key, subject_kind, host/endpoint/IP references as applicable, check_type, status, reason_code, verdict, observed_at, collected_at, adapter/schema versions, payload, attribution/confidence | Unique run/logical_check_key; subject-specific CHECK constraints; no arbitrary unvalidated payload |
| `result_artifact` | check_result_id, artifact_id, relation | Scoped FK; many evidence items can support one result |
| `provider_observation` | run_id, provider_label, category, hostname/IP/request origin, method, confidence, supporting_result_id | Observed entity, not a contractual processor |

A `check_result` has one logical subject: `hostname`, `endpoint`, `ip` or `url`; URL checks include parent host and normalised redacted URL. Validate required/forbidden reference combinations. Do not use an unchecked generic `subject_id` pointing to multiple tables. IP-level Shodan results link to relevant run hosts through a scoped association table; never copy a CVE onto every DNS hostname without attribution assessment.

`status`: `succeeded`, `failed`, `skipped`. `reason_code` explains failures/skips such as `dns_unresolved`, `blocked_destination`, `invalid_tls`, `non_html`, `not_licensed`, `budget_limit`. Verdict is check-specific, for example `match/no_match/unknown` or `valid/invalid/unknown`. A successful reputation lookup can return `no_match`; a timeout cannot. Retry attempts live in jobs, not duplicated logical results. On-demand rechecks become a new run in Phase 1.

## 4. Technical interpretation

| Record | Required fields | Constraints/use |
|---|---|---|
| `finding` | run_id, rule_id/version, stable subject key, severity, confidence, attribution, message_key, message_parameters, source_result_ids via relation | Unique run/rule-version/subject/issue key; no translated message as primary identity |
| `finding_revision` | finding_id, sequence, actor_id, disposition, note, created_at | Unique finding/sequence; `unreviewed/confirmed/false_positive/needs_validation`; no business risk acceptance |
| `technical_summary` | run_id, category, rule_version, facts, limitations, source links | Categories `location/providers/security`; facts structured, not unsupported prose |
| `analyst_annotation` | case/run/finding scoped references, actor_id, body, revision, expires_at | Plain text by default; no executable markup |

Severity: `informational/low/medium/high/critical`. Confidence: `low/medium/high/unknown`. Attribution: `hostname_supported/ip_only/shared_infrastructure/unknown`. Provider `verified=true` is a separate retained source flag, not our own confidence or hostname proof. Counts group duplicate service findings explicitly and never invent a composite supplier security score.

## 5. Reports and artifact records

| Record | Required fields | Constraints/use |
|---|---|---|
| `artifact` | workspace_id, case scope or report-version scope, backend, opaque locator, version_ref, media_type, bytes, sha256, state, source/rights policy, created_at, expires_at | Exactly one ownership scope; no public URL; `staged/committed/deletion_pending/deleted/corrupt` |
| `report` | workspace_id, assessment_id, created_by | Logical grouping only; grants never apply to all future versions |
| `report_version` | report_id, assessment_id, version_number, source_run_id, snapshot_schema, snapshot_json, snapshot_hash, state, preparer, policy_version, issued_at, expires_at, revision | Unique report/version; snapshot frozen after preparation; never join live facts for an issued view |
| `report_evidence` | report_version_id, report-owned artifact_id, display_label, provenance reference, inclusion rights | Report-scoped derivatives/copies; never authorise download of source-case objects |
| `report_rendering` | report_version_id, locale, renderer/template/catalog versions, artifact_id, manifest_artifact_id, state | Unique version/locale; once issued, immutable; PDF hash lives in manifest, not recursively within itself |
| `approval` | report_version_id, actor_id, snapshot_hash, policy_version, timestamp | Approval invalidated by content/policy changes; independent reviewer where required |
| `report_grant` | workspace_id, report_version_id, user_id, can_download, expires_at, revoked_at, granted_by | Unique version/user; explicitly issued version only |
| `tprm_handoff` | report_version_id, rendering locale/hash, actor_id, confirmed_at, external_reference, note | Append-only confirmations/corrections; plain external reference is enough, never fetched automatically |

Report copies may outlive their source run; provenance IDs are references, not a requirement to retain all source rows indefinitely. Preserve minimal provenance in the snapshot; do not let cascading FKs delete a retained report when a source run expires. Use a nullable source reference on expiry plus immutable source identifier/hash in the snapshot, or retain a minimal source tombstone. Do not leave confidential facts in supposedly minimal tombstones.

## 6. Operational records and indexes

`job`: case/run scope, kind, logical_key, payload_schema, bounded input, state, priority, available_at, attempts, lease_owner, lease_generation, lease_until, heartbeat_at, cancellation flag, safe last_error_code. Unique logical key within run/report operation. `job_attempt`: job/generation, start/end, outcome, safe diagnostics, provider reservation link. See [collection](collection.md) for transitions.

`quota_reservation`: provider credential reference (not the key), job/generation, estimated credits, period, state and reconciliation time. `provider_usage`: credential/period counters, provider balance/time, version. `audit_event`: workspace, actor/system identity, action, object type/ID, outcome, correlation ID, timestamp and allowlisted metadata. `idempotency_record`: actor/scope/operation/key/digest/result reference/expiry. `retention_hold` and `deletion_record` carry scoped reason/actor/deadlines, without retaining deleted evidence content.

Initial indexes: grants by `(user_id, scope_id)`; cases by `(workspace_id, created_at, id)`; runs by `(assessment_id, created_at, id)`; hosts by `(assessment_id, name_ascii)`; results by `(run_id, check_type, status)`; findings by `(run_id, severity, id)`; jobs partial index on `(available_at, priority, id)` for claimable states plus lease expiry; artifacts by `(state, expires_at, id)`; renderings by `(report_version_id, locale)`; audit by `(workspace_id, created_at, id)`. Index referencing FK columns used for joins/deletion. Add JSONB indexes only for measured queries.

## 7. State and coverage semantics

| Aggregate | States and rules |
|---|---|
| Run | `queued → running → complete/partial/failed/cancelled`; `waiting_provider` may suspend running; cancellation uses a separate `cancel_requested_at` until terminal |
| Job | `queued → running → succeeded/failed/skipped/cancelled`; retryable failures return to `queued` with `available_at`; quota wait uses `waiting_provider`; only finite attempts for transient errors |
| Report version | `preparing → draft → issuing → issued`; optional `review/approved` before issuing; preparation/issuance failures return to a retriable state with explicit error, never fake issued status |
| Rendering | `queued/rendering/ready/failed/issued`; `ready` is unpublished output, not a user-visible final report |

Run completion requires discovery to be terminal, job production closed and no nonterminal jobs. `complete` means all planned applicable checks concluded with valid results or expected exclusions. Invalid TLS with an explicit skipped screenshot is a complete observation, not necessarily a collection failure. `partial` means usable results with incomplete discovery, failed required checks, missing entitlement or budget truncation. `failed` means no useful collection could be made; `cancelled` preserves useful partial data. An unknown verdict can be validly returned but must reduce evidence coverage when the question remains unanswered.

Store counts separately: discovery names (including wildcard patterns), concrete hosts, resolved endpoints, TLS-eligible endpoints, planned/applicable/completed/failed/skipped checks. Hosts with mixed endpoints can have mixed status. Report denominators and exclusion reasons; do not sum overlapping host categories as if they were mutually exclusive. Freeze coverage with the report.

## 8. Transactions and migrations

Short transactions cover: case+owner+audit; run+first job+idempotency; job claim; job completion+results+next jobs; grant+audit; frozen snapshot+artifact requirements; report publication; expiry/deletion bookkeeping. Files/provider calls happen between transactions with explicit staged states. No transaction remains open during HTTP collection or rendering.

Alembic migrations are reviewed code. Autogeneration is a draft, especially for renames and non-table objects; inspect constraints, indexes, RLS policies, grants and data conversions explicitly. [Alembic autogeneration](https://alembic.sqlalchemy.org/en/latest/autogenerate.html). Test from an empty DB and from the previous schema with representative records. Use forward-compatible expand/contract changes; do not promise a lossless downgrade after destructive changes. Migration role is never the web runtime role. Test retention and report-only FKs before applying cascade rules.
