# Trademark policy

Gaprism is the name of this project. This page says how the name may be used.

It does not limit what the [Apache License 2.0](LICENSE) lets you do with the code: you may use,
change, copy and sell the software. Section 6 of the licence leaves the name out: it gives no right
to use the maintainer's names, marks or product names, except to say where the software comes from.
This policy fills that gap, so that people can tell the project from copies and forks of it.

The name is not registered as a trademark yet. This policy applies whether or not it is.

## Always fine, no need to ask

- Running Gaprism for yourself or your organisation, unmodified or modified, and calling it Gaprism
  inside your organisation.
- Saying that you use Gaprism, that your tool is based on it or works with it ("based on Gaprism",
  "reads Gaprism's JSON export"), in text, talks, articles, reviews and comparisons, as long as it
  is true and does not suggest that the project backs you.
- Linking to the project, and using the name when you contribute to it (issues, pull requests,
  translations).
- Passing on unmodified releases, with the [LICENSE](LICENSE) and [NOTICE](NOTICE): a mirror, a
  container image built from a release, a package for a distribution.
- A distribution package that carries only the patches needed to build or run the software may keep
  the name if it says that it is patched.

## Ask first

Write to the contact in the [README](README.md#contact). Permission is given in writing, for a
named use, and can be withdrawn if the use turns out to mislead.

- Naming a product, service, company, domain, app, package, social account or event with Gaprism or
  with a name that can be confused with it (Gaprism Something, Gaprizm), where it concerns
  software or services in the same field.
- Offering Gaprism to others as a hosted or managed service under that name, for a fee or not. You
  may host it, and you may say it is "based on Gaprism"; the name of the service is yours to choose.
- Publishing a modified version under the name. Configuration, translations and the patches of a
  distribution package are not modifications in this sense; changed behaviour is.
- Presenting yourself as official, as a partner of the project, or as endorsed by it, or using a
  logo of the project (there is none yet).

## If you fork it or run it for others

- Choose a name of your own, and say once, with a link, that your work is "based on Gaprism" or a
  "fork of Gaprism".
- Set `USER_AGENT`. The application introduces itself with this string in its HTTP requests to the
  sites it assesses; its default names Gaprism and the project's address. If you run it for other people, or change
  what it does, put your own name and a way to reach you in it
  ([docs/deploy.md](docs/deploy.md#what-leaves-your-network) lists the setting), so that the
  owners of the sites it visits reach you and not the project.
- Do not give the project's address or contact as yours.
